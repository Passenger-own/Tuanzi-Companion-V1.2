# 竞品调研与产品定位

> 阶段：0-1 立项期 ｜ 结论：**确立「3D 毛绒视觉 + 防打扰机制 + 效率工具一体化」差异化定位，选型 DeepSeek 作为 AI 对话引擎**

## 1. 调研背景

桌面宠物赛道长期存在「有形象、无陪伴；有陪伴、无效率」的断层。立项期对 **7 款核心桌宠产品**进行功能与体验拆解，验证机会点。

## 2. 竞品拆解（7 款）

| 产品 | 视觉表现 | 交互方式 | 效率工具 | AI 能力 | 核心短板 |
| --- | --- | --- | --- | --- | --- |
| Shimeji | 2D 像素风，形象较粗糙 | 爬窗/拖拽彩蛋 | 无 | 无 | 无实用功能，纯娱乐 |
| Bongo Cat | 2D 简笔画 | 键盘联动敲击 | 无 | 无 | 功能单一，无陪伴纵深 |
| Live2DViewerEX | Live2D 精美人设 | 点击/视线跟随 | 无 | 无 | 只看不聊，无工具集成 |
| 元气桌面 | 壁纸+桌宠混合 | 点击互动 | 无 | 无 | 桌宠为附属模块，交互浅 |
| 天选姬桌面宠物 | 3D 形象 | 点击/语音 | 无 | 简单语音指令 | 无 LLM 对话，无防打扰设计 |
| DPET 桌面宠物 | 2D 卡通 | 点击/投喂 | 无 | 无 | 随机弹动打断工作流 |
| Widgetable（移动端） | 2D 小组件 | 点击/养成 | 无 | 无 | 仅移动端，桌面场景缺失 |

## 3. 共性痛点归纳

1. **形象粗糙**：主流产品以 2D 像素/简笔画为主，缺乏「想一直摆在桌面上」的视觉品质；
2. **交互打断工作流**：随机动作、随机弹窗不分时机，办公场景下被用户主动关闭率高；
3. **无效率工具集成**：陪伴与效率割裂，用户无法在桌宠上完成任何一件「正事」；
4. **无真正 AI 对话**：均无 LLM 驱动的连续对话能力，更无人设管理。

## 4. 差异化定位

结合用户需求（情感陪伴 + 办公友好）与隐私需求（对话数据敏感），确立：

> **3D 毛绒视觉 + 防打扰机制 + 效率工具一体化**
>
> - 3D 毛绒视觉：3D 建模渲染转 GIF 序列，原生直出保证品质与性能；
> - 防打扰机制：两档专注模式 + 八状态交互系统 + 优先级分层与事件排队，规范 AI 弹窗与交互节奏；
> - 效率工具一体化：待办 / 计算器 / 记事本 / 快捷键 / 健康提醒内建于宠物入口；
> - 隐私：**数据本地存储、对话零二次分发**，仅当前对话上下文经 API 请求模型。

## 5. AI 对话引擎选型（DeepSeek / 通义千问 / 豆包 三维对比）

| 维度 | DeepSeek | 通义千问 | 豆包（Doubao） |
| --- | --- | --- | --- |
| 中文拟人化对话质量 | 高，口语化与角色扮演表现稳定 | 中高，偏正式 | 高，拟人化好 |
| API 成本 | **低**（输入/缓存命中成本优势明显） | 中 | 中低 |
| 接入与稳定性 | OpenAI 兼容协议，接入成本低，SSE 流式支持完善 | DashScope 协议，接入一般 | 方舟平台，接入一般 |

**选型结论：DeepSeek**。兼顾拟人化对话质量与 C 端产品最关键的成本敏感性；OpenAI 兼容协议 + SSE 流式能力满足 V1.1 流式输出改造；配合本地历史存储与摘要压缩，实现「对话零二次分发」的隐私承诺。
